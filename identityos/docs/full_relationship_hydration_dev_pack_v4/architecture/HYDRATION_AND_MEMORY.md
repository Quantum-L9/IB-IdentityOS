# Hydration and Memory v4

## Hydration is broader than memory retrieval

Hydration means resolving the minimum sufficient, authorized behavioral and contextual state for **both sides of a relationship** before runtime activation.

```text
agent identity/persona branch       counterpart identity/preference branch
             \                                 /
              \                               /
               +---- RelationshipArchetype ---+
                             |
                  EffectiveRelationshipProfile
                             |
             consent / policy / trust / purpose
                             |
                        minimization
                             |
                         RuntimePayload
```

## Context memory scopes

- `IDENTITY_CANONICAL`
- `RELATIONSHIP_SCOPED`
- `SESSION_SCOPED`
- `ACTOR_LOCAL`

## Preference memory

Preference evidence may be durable, but it MUST enter through the canonical memory admission/write path. IdentityOS owns the preference semantics and resolution rules. The memory service persists admitted evidence. Graphiti and embeddings are projection/retrieval layers only.

## Epistemic classes

`FACT != SHARED_ASSERTION != OBSERVATION != INFERENCE`

Preference evidence additionally preserves its origin, such as explicit statement, correction, repeated behavior, rejection, accepted suggestion, outcome, research, or model inference.

## Outcome-evidenced learning

```text
resolved behavior
-> interaction
-> outcome / correction / acceptance / rejection
-> immutable evidence
-> governed preference/relationship update
-> stronger next hydration
```

Learning MUST NOT silently promote inference to fact or cohort prior to individual truth.

## Consent

Consent remains action-scoped. Recording, storage, hydration, disclosure, sharing, and promotion are distinct operations.

## Runtime invariant

A relevant memory hit does not automatically enter the runtime. A preference embedding does not automatically become a preference. All material context and behavioral state must pass provenance, consent, visibility, policy, trust, purpose, relationship scope, and minimization gates.
